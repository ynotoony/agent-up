# Agent Up

> 对 Agent 友好，而非人类友好。

## 你可能已经遇到了这些问题

1. 让 Agent 改个功能，它不看项目情况，上来就改，方向错了你才发现。
2. 昨天干到一半，今天新开会话，它什么都不记得，你只能从头再讲一遍。
3. 让它修个小问题，它顺手改了一大堆不相干的文件。
4. 它说"做完了"，但没有验证记录，也没有人检查过。
5. 你提的新需求记在聊天里，过两天就忘了。
6. 项目文档和代码对不上，越放越没人看。

## 因此我们做了这些事情

1. **做了一套工作协议**：Agent 先读项目说明，盘点完给你一张清单，你同意了才改。不做代码生成，也不猜你的业务。
2. **做了三道关卡**：写代码、检查、提交，由三个不同的 Agent 分开做。写代码的不给自己打分，检查没通过就不能提交。"完成"从它说了算，变成有记录、有人查。
3. **做了进度记录**：做了什么、验证过没有，全写成文件放在项目里。会话断了也不怕，新会话读完文件接着干。进度从"在聊天里"，变成"在项目里"。
4. **做了需求登记**：你说"加个需求"，它先记进队列，排好状态，不打断手头的活。需求从"说了就忘"，变成"条条有下文"。
5. **做了按需安装**：一开始只装 7 个文件，其他的等真的用到再加。老项目只补缺的，不改你已有的东西。
6. **做了文档联动规则**：改个错别字，文档不会乱动；接口、目录、流程真的变了，相关文档才更新。文档从"越养越乱"，变成"该动才动"。
7. **做了读取顺序**：Agent 按任务只读需要的那几份文件，不整个仓库翻一遍。
8. **做了边界说明**：每个任务写清楚能改什么、不能改什么。不做自动 push 和自动部署，这些由你决定。

## 怎么运作

每个改动都走同一条流水线：

```text
1. 盘点   看懂项目，给你一张清单
2. 确认   你同意，才动手
3. 实施   改代码 + 验证，记下进度
4. 检查   换一个 Agent，只看不改
5. 提交   检查通过才提交，只碰清单里的文件
```

## 安装

前置条件：一个支持 Skills 的 agent 环境。

```bash
git clone https://github.com/ynotoony/agent-up.git ~/.agents/skills/agent-up
```

## 使用

在目标项目里输入 `/agent-up`。第一次运行：盘点 → 给你清单 → 你确认 → 装好。之后每个任务自动走流水线；断了就说"继续剩余任务"；加需求，开个新会话说"加个需求"。
